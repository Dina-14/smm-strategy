# Шаг за шагом — платформа персональной SMM-стратегии

MVP по [prd.md](prd.md): человек отвечает на 10 вопросов и получает персональную SMM-стратегию,
пошаговый план на 30 дней, шаблоны и короткие статьи простым языком.

Статический сайт без сборки и зависимостей (HTML + CSS + JS). Работает на любом статическом хостинге
(Netlify, Vercel, GitHub Pages, Tilda-zero-block, nginx).

## Запуск локально

```powershell
powershell -ExecutionPolicy Bypass -File serve.ps1
```

Затем открой http://localhost:8080. Подойдёт и любой другой статический сервер
(`npx serve`, `python -m http.server`).

## Настройка перед запуском

Всё в [js/config.js](js/config.js):

- `yandexMetrikaId`, `gaMeasurementId` — счётчики. События воронки: `diagnostic_start`, `diagnostic_step`,
  `diagnostic_complete`, `plan_step_done`, `plan_step_feedback`, `template_copy`, `template_download`,
  `strategy_print`, `strategy_saved`, `feedback_sent`.
- `feedbackEndpoint` — куда отправлять форму обратной связи (Formspree, Tally, свой API). Пока пусто,
  сообщения сохраняются только в браузере пользователя.

## Структура

```
index.html            каркас, шапка, подвал
css/styles.css        стили (токены цветов, мобильная вёрстка, печать)
js/config.js          настройки
js/data/              контент: ниши, вопросы, площадки, шаблоны, статьи
js/strategy.js        генератор стратегии и контент-плана
js/plan.js            план на 30 дней
js/app.js             роутер (#/…), экраны, состояние, аналитика
serve.ps1             локальный сервер для разработки
```

## Как редактировать контент

Методология живёт в `js/data/` и правится без программирования логики:

- **Новая ниша** — добавь объект в `SMM.niches` (`niches.js`). Она сама появится в диагностике.
- **Статья** — добавь объект в `SMM.articles`, обнови `updated`.
- **Шаблоны** — `templates.js`.

Тексты пишутся и проверяются практикующими SMM-специалистами (раздел 3 PRD). Ежеквартально обновляй
`updated` у статей и `contentReviewedAt` в конфиге.

## Ограничения MVP и следующие шаги

- Нет бэкенда: стратегия и прогресс хранятся в браузере. Аккаунты, синхронизация между устройствами,
  несколько стратегий (F6.2–F6.3) и email-напоминания (F3.5) требуют сервера. Следующий этап по PRD 7.2 —
  Next.js + БД + авторизация; данные из `js/data/` и логика `strategy.js`/`plan.js` переносятся как есть.
- Генерация детерминированная (шаблон + правила). ИИ можно подключить позже для переформулировки текстов
  под конкретный бизнес, не меняя структуру.
- Открытые вопросы PRD (раздел 12) — рынок/язык, приоритетные площадки, набор ниш — влияют на `niches.js`
  и `platforms.js`. Сейчас: русский язык, 5 ниш + «Другое», Instagram / TikTok / Telegram / ВК / YouTube.
